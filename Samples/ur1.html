Issues found in the machine transcription

  • Script drift: 32 English words were written in Urdu script (or vice versa), e.g. transliterations like سپیکر for 'speaker'. They were accepted as equivalent here, but a stricter scorer would count them all as errors.
  • 23 true substitutions (phonetic mishears), e.g. 'نہ' -> 'نوع', 'کوئی' -> 'کی', 'وقت،' -> 'بہت', 'انسان' -> 'سال'.
  • 12 deletions (words missing from the machine output): 'جب', 'آپ', 'کے', 'اندر', 'موجود', 'اس'.

Suggestions to reduce WER

  • Force script fidelity: instruct/configure the ASR to keep English words in Latin script during code-switching; or add an inverse-transliteration post-processing pass.
  • Improve acoustic robustness for mishears: cleaner audio (less noise, better mic), a domain lexicon / hotword list with the expected vocabulary, and a spelling-correction post-processing pass for known confusion pairs.
  • Check for audio dropouts / aggressive VAD trimming causing missed words; lower the VAD threshold or use overlapping chunks.

AI Analysis (GLM)

Issues

  1. Substitution Errors: Frequent character-level substitutions (e.g., "نہ" → "نوع") and word-level confusion (e.g., "وقت" → "بہت") degrade fluency.
  2. Insertion Errors: The model inserts Urdu particles ("جو", "اسی") that do not exist in the ground truth, inflating the word count.
  3. Deletion Errors: The model frequently drops Urdu function words ("کے", "اور") and prepositions ("اندر").

Suggestions

  1. Audio Pre-processing: Apply noise reduction and high-pass filtering to minimize background noise, which often causes character confusion.
  2. ASR Configuration: Enable "Code-Switching" or "Bilingual" language models in the ASR engine settings to better handle mixed-language audio.
  3. Post-Processing: Implement a spell-checker or language model-based filter to correct common substitutions (e.g., "نوع" → "نہ") and remove extraneous insertions.
  4. Audio Quality: Ensure the recording volume is consistent and free from clipping to improve phoneme accuracy.
