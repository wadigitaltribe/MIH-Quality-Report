Issues found in the machine transcription

  • Insertions dominate: 49 inserted words (58% of all errors). Without insertions the WER would be 15.19% instead of 35.86%.
  • The ASR appends its own English translations/paraphrases of Urdu sentences instead of only transcribing. Examples: "then Pakistan can become stronger, productive and successful. Thank you.   • Script drift: 45 English words were written in Urdu script (or vice versa), e.g. transliterations like سپیکر for 'speaker'. They were accepted as equivalent here, but a stricter scorer would count them all as errors.
  • 33 true substitutions (phonetic mishears), e.g. 'ke' -> 'کی', 'bada' -> 'بڑا', 'digriyan' -> 'لگنیاں', 'Hamara' -> 'Our'.
  • 3 deletions (words missing from the machine output): 'ko', 'banana', 'hoga.'.

Suggestions to reduce WER

  • Disable translation behaviour: set the ASR task to 'transcribe' (not 'translate'), or instruct the model to output verbatim speech only, in the original language mix.
  • Post-process: drop sentences that duplicate the meaning of the immediately preceding segment in another language (near-duplicate detection before scoring or delivery).
  • Force script fidelity: instruct/configure the ASR to keep English words in Latin script during code-switching; or add an inverse-transliteration post-processing pass.
  • Improve acoustic robustness for mishears: cleaner audio (less noise, better mic), a domain lexicon / hotword list with the expected vocabulary, and a spelling-correction post-processing pass for known confusion pairs.
  • Check for audio dropouts / aggressive VAD trimming causing missed words; lower the VAD threshold or use overlapping chunks.

AI Analysis (GLM)

Issues

  1. Substitution Confusion: The model confuses homophones or similar-sounding words across languages, such as "degrees" → "but" and "deta" → "focuses".
  2. Insertion Runs: The transcript contains long, unbroken strings of incorrect text inserted into the middle of sentences, inflating the WER significantly.

Suggestions

  1. Audio Pre-processing: Apply noise reduction and audio normalization to improve clarity, as background noise often causes the model to insert random words.
  2. Post-Processing Filtering: Implement a rule-based filter to remove common filler words (like "then", "of", "gives") that are frequently inserted in error.
  3. Punctuation Restoration: Configure the ASR to enforce strict punctuation rules to prevent run-on sentences and break up the insertion runs.
  4. Language Model Tuning: Adjust the language model weights to penalize frequent code-switching errors and prioritize the dominant language context.
